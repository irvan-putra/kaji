Wording left as is on purpose, and one correction

Sanggup: asking learners to get human review

Where: Coding lesson and its tools review page. Coding path · Tools review

What: The lesson asks the learner to get a specific piece of code reviewed by a person. Other learning paths also ask for feedback or mentor sign-off.

Why: This is advice for a future learning exercise, not a claim that a person wrote or checked Sanggup. Replacing person with AI would change the lesson. The site now carries the AI-assistance disclosure separately.

Choice: Keep the human-feedback exercise, or request an AI-only alternative with its limits stated. No lesson requirement was changed in this wording pass.

Status: Kept as lesson advice.

APK release comments: corrected, not left unchanged

Where: Nine sign-test-apk workflows: bidik, denyut, jin, kemas, menit, onda, saku, sapa and unggah. Saku workflow · Jin workflow

What: An old comment said a reviewed person attaches the APK by hand. These workflows actually upload an artifact and have read-only repository permissions; they do not create a release.

Why: The previous decision to leave that sentence was wrong. An account name on a release does not prove a human uploaded or reviewed it. The comments now say artifact publication is a separate step and the workflow does not establish human review. AI-assisted release publishing must not be called human review.

Choice: Keep the factual artifact-only description. If a human approval gate is wanted, that would be a separate workflow change, not something this wording edit claims to implement.

Status: Corrected in all nine workflow comments.

Tindak: a mock review state, not an endorsement

Where: Review prototype and archived webxdc canvas. Review prototype · Prototype source

What: The mock screen says Reviewed by: no one yet. Proved: nothing, next to its mock-entries label.

Why: That text denies that any review has occurred. It is a prototype state, not a claim that a named person reviewed the project. The surrounding explanation describes what signed reviews could look like, not an implemented verification service.

Choice: Keep the mock state, or rename it to No reviewer recorded (demo only) if clearer. No real reviewer or signature was added.

Status: Kept as an explicit unreviewed mock state.

Kaji: attributed research and quotations

Where: Talk notes and research pages, for example the attention talk. Attention talk note · AI safety talk note

What: Research notes retain speakers statements, quotations, titles and advice about human judgment, code review and responsibility.

Why: Those words describe or quote another source. Replacing person or human with AI would misquote that source or change the argument. This does not exempt Kaji own claims about who checked a source: those must name Instinct when it did the checking. The new disclosure identifies how the page was made.

Choice: Keep attributed source wording, or request clearer quote boundaries and separate AI-written summaries where an attribution is ambiguous. This was an authorship pass, not a new verification of every research claim.

Status: Kept source attributions and quotations; added page-level disclosure.
