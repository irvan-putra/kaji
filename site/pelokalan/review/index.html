Pelokalan: contribution ideas

Options review only. Nothing here is built, proposed upstream or decided. Pelokalan is Herpiko's web-based gettext translation editor (Go + htmx, MIT); the fork for any work is irvan-putra/pelokalan. Every option was checked against the source at commit d565b6f (24 Nov 2026).

Short answer. Start small and standard: CI and tests land first (recommended set marked recommended). Anything that changes translator-facing behavior or adds a feature needs Herpiko's agreement on shape before a PR is written. Any PR will state it was built with AI assistance.

A. Ready now - small, standard, low risk

GitHub Actions running build, go vet, the test suite and golangci-lint on push/PR. The repo has make lint but no CI at all.

Effort: small · Risk: low · Buy-in: not needed. Deliberately does not change any code.

netsafe (the SSRF guard), the auth and SameOrigin middleware, and blobstore have no tests. Pure additions.

Effort: small-medium · Risk: low · Buy-in: not needed. Deliberately does not touch behavior.

The README invites contributions but there is no guide: setup, tests, commit conventions, how to propose.

Effort: small · Risk: low · Buy-in: not needed, though Herpiko may reword conventions.

A security reporting policy and automated Go module update PRs.

Effort: small · Risk: low · Buy-in: not needed.

Property-style tests: write(parse(x)) == x across generated entries (plurals, obsolete, multiline, contexts). Catches parser/writer drift in the heart of the app.

Effort: medium · Risk: low · Buy-in: not needed.

B. Translator workflow - features, need Herpiko's buy-in on shape

Read-only JSON and a shields-style SVG (percent translated, fuzzy count) per project/language, extending the existing public members API. Upstream projects could embed live translation status.

Effort: medium · Risk: low-medium · Buy-in: API shape. Deliberately read-only, no auth, no write API.

Warn while typing when a translation conflicts with how the project glossary renders a term. The inconsistency data already exists on glossary pages; this surfaces it at the moment of translation.

Effort: medium · Risk: medium · Buy-in: behavior. Deliberately a warning, never a block.

Extend the existing placeholder/newline validation: punctuation parity, leading/trailing space, URL and email parity. Per-project toggles.

Effort: medium · Risk: low · Buy-in: which checks default on.

One queue across a project listing unreviewed AI drafts and fuzzy entries, so people review instead of retyping. Matches the project's stated goal of letting contributors focus on reviewing.

Effort: medium · Risk: medium · Buy-in: UX design.

Interoperability with CAT tools. Big, and only worth it if Herpiko wants that audience.

Effort: large · Risk: medium-high · Buy-in: definitely. Deliberately parked unless he asks.

C. Achievements-adjacent

Reward clearing machine-translated drafts (the orange bot markers). Nudges the exact behavior the project wants: human review of AI output.

Effort: small-medium · Risk: low · Buy-in: badge design.

Celebrate collective wins on the project page: a language reaching 100%, N strings accepted upstream. Complements the personal badges.

Effort: medium · Risk: medium · Buy-in: feature.

D. UX and accessibility

ARIA roles are sparse; add a skip link, dialog focus handling, focus placement after htmx swaps, contrast check. Incremental fixes.

Effort: medium · Risk: low · Buy-in: mostly not needed.

CSS variables are already in place; add prefers-color-scheme plus a manual toggle.

Effort: medium · Risk: low-medium · Buy-in: design.

Breakpoints exist, but the two-pane desktop-style editor is the core screen; make it genuinely usable on phones.

Effort: medium · Risk: medium · Buy-in: design.

E. Interface languages and docs

The i18n maps are test-enforced; adding e.g. Javanese or Sundanese is straightforward and could be translated using Pelokalan itself.

Effort: small-medium · Risk: low · Buy-in: which language.

The app has its own plural-expression parser; cross-check its language table against CLDR data.

Effort: small · Risk: low · Buy-in: not needed.

Screenshots/GIFs of the editor and badge pages, plus an Indonesian README.

Effort: small · Risk: low · Buy-in: not needed.

App + PostgreSQL in one command. make prep already does the database part; this completes it.

Effort: small · Risk: low · Buy-in: not needed.

Deliberately not proposed

  • Security headers or a CSP: already in place (nosniff, frame denial, referrer policy, sandboxed user content).
  • Interface i18n framework fixes: the two-map system is already enforced by tests.
  • A hosted/managed Pelokalan service, and any rewrite of the stack.
