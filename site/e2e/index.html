e2e: a test framework where you choose how much the agent does

Status: read from the public repository and e2e.com on 25 Nov 2026. Nothing was installed or run, and it has not touched any of our apps. Facts below are the project's own claims.

What it is

Source: https://github.com/e2e-inc/e2e (Apache-2.0, site e2e.com). A TypeScript end-to-end test runner for web, iOS and Android. A test can be plain locators and assertions with no model, goals in natural language (agent.act, agent.assert), or a mix of both in one test. The repository showed about 14,200 stars when read.

  • Web runs in Chromium, Firefox and WebKit through Playwright. Mobile runs on iOS simulators, Android emulators and physical devices.
  • Cache replay: a passing agent.act step is recorded once a later check verifies it. CI then replays the recording with no model call, and the agent takes over only if the app changed. agent.assert, waitFor and extract always call the model.
  • e2e explore: give it a goal instead of a test file, and it drives the app and reports findings with severity, repro steps and screenshots.
  • Bug bash: a coding agent runs several explores, one per area or persona, then writes a repro test for each finding. A finding counts as a bug only if that test fails for the reported reason.
  • MCP server (npx e2e mcp): lets Claude Code, Cursor or similar open a live session on the app. It needs no model.
  • Bring your own model: any AI SDK model, a subscription login, an API key, OpenRouter or a local server. Credentials are filled by name and redacted from model input.
  • Needs Node.js 24.8 or newer. Mobile tests need the Android SDK with an emulator, or Xcode for iOS.

How it fits with mobile-agent-testers

Both use an agent to drive a real phone and report bugs, but they sit at different layers. See mobile-agent-testers for the other one.

Using them together

  1. Find, then lock in. Run mobile-agent-testers over an APK to find problems across personas. Turn each real finding into an e2e test, so the bug stays fixed and CI can replay it cheaply.
  2. Persona sweeps without a second tool. e2e's own bug bash can do a small version of the same thing, with agents defined per persona. The built-in personas in mobile-agent-testers are still the bigger ready-made set.
  3. Our Android apps. Kapan, Tuju, Kokok and others ship as APKs (see the APK page). A first try would be one app and one flow, for example adding an alarm in Kokok and checking it survives a relaunch.

What stops us today

  • Not tried: we have not checked whether it works on a plain Android app that is not written in a JavaScript stack. The repository lists example projects for Flutter, Compose, SwiftUI and others, which suggests it can.
  • Model key: any agent step needs a model. Nothing is stored for this. Whether Fenrir's Qwen route works with it is unknown, so unverified.
  • Setup cost: an emulator on a CI runner, Node 24.8, and tests added to each app's repo. Our rule is no new repos without Irvan's yes, so tests would go into existing repos.
  • AI disclosure: any bug found this way is AI-reported and unreviewed, and should be labelled that way.
