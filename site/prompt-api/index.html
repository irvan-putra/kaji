What the slides say

  • Title: "Everything Has an API If You're Willing to Prompt", Bagas Wastu (@bgwastu).
  • "Boostcamp": three phone screenshots of the Boostcamp workout-tracker app, captioned "Ditch the spreadsheet with our smart program tracker", "Weight progressions automatically calculated for you", and "Custom workout tracker to log your training and create routines". The app details are as shown on the slide; we made no independent assessment of the app.
  • "Apa yang dikerjain agent" (What the agent did): the speaker reports that an agent (1) got in via ADB and found Boostcamp's local database, (2) found the active Firebase login token, (3) wrote a Python script calling Boostcamp's private API, and (4) built a dashboard. The slide footer reads "All in <15 minutes".

How to read this

  • Reported, not verified. The slide alone does not establish whose device or account was used, the permission scope, or the "<15 minutes" timing. Read it as the speaker's account of a personal experiment, not a demonstrated result.
  • The authorization boundary is the part that generalizes. Ownership alone does not settle it: you need explicit permission covering the device, the account, the data and the intended API use, and the service's rules still apply. A login token copied out of an app is a credential: handle it like a password, never share it, and never use one that is not yours.
  • Private APIs are fragile by construction. They can change without notice, and the service's terms may restrict this kind of use, so check the current terms for whatever you build on. We make no blanket legal claim in either direction.
  • Deliberately not a how-to. This page gives no extraction steps, commands or scripts, and the Sanggup companion exercise is a written boundary check, not a data pull from a real app.

What we keep

The idea worth keeping: an agent with device access can turn an app with no official public API into a data source, cheaply. Pair it with the boundary questions before anything else: whose device, whose account, whose permission, and what happens to the token afterwards. Sanggup's Coding path carries the written exercise: "Ask whose device, whose account, whose permission".
