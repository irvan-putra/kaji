CodingTool: small developer utilities, with per-tool data boundaries

CodingTool.dev is a collection of browser-based developer utilities, not an IDE, a coding model or an automatic software engineer. It offers hundreds of tools without signup. Counts differ across its pages, so the useful question is which tool solves the task and where that tool processes the input.

Local-first is not universally offline or tracking-free. Its privacy policy describes local, hybrid and server-based tools, along with analytics and advertising. Check the processing label for the actual mode before pasting anything sensitive.

Three examples show the difference

JSON Formatter

Formats and validates JSON. The tool describes its core processing as local in the browser; its FAQ lists a 10 MB limit. Use synthetic JSON to check indentation, parse errors and expected output before trusting a workflow. This review did not submit data or audit the implementation.

HTML to Markdown

Paste/upload mode is described as local conversion. URL mode instead sends the URL to a server fetcher, with a stated 2 MB response limit and 10-second timeout. The vendor says fetching is transient. Do not mistake URL mode for a fully offline operation, or send a private signed URL assuming it stays only on the device.

Prompt Privacy Checker

The page describes deterministic pattern checks/redaction, not a model that understands all confidential context. It lists a 2 MB input limit. False positives and missed secrets remain possible; a clean result is not permission to disclose a prompt or evidence that every identifier is gone.

A collection, not one data contract

Formatting, conversion, previewing and network-dependent utilities have different needs. A working local transformation does not prove that every tool, asset, advertisement or optional feature works without a network.

Privacy policy versus the broad claim

The policy dated 30 September 2026 describes per-tool local/hybrid/server notices. It also lists Google Analytics, AdSense and TinyAdz, cookies and local storage. Broad marketing language about local processing should not be read as a no-tracking guarantee for the website. Advertising was visible during the public-page review.

Local core processing can reduce where the input is sent, but that claim was not verified by source-code or network inspection here. Do not test the claim with real passwords, keys, customer data, production logs or private documents.

Can another program use it?

The site advertises MCP/WebMCP-related discovery. That is a lead for an integration review, not proof that every utility has a stable external API or can be called without a browser. No protocol contract, installation, machine call or automation was tested.

A practical way to use it

  1. Choose the exact utility and read its input limits and processing notice, including mode-specific exceptions.
  2. Start with invented sample data. Check the output against the format you need rather than assuming formatting also verifies meaning.
  3. Use an approved offline/local program for secret-bearing work unless the data path and dependencies have been independently reviewed.

No account, secret input, file submission, network-tool request, installation or payment was made. Public pages were read only. This is a feature/data-flow explanation, not a security certification.
