Secrets: three jobs, three tools

Design review only. Nothing here is built, installed, moved or paid for. Saku stays parked; its public README still describes a documentation-only design checkpoint, with no real vault storage or autofill.

Short answer. Do not pick one tool for everything. A phone password vault, secrets for apps and bots, and encrypted config files in git are three different jobs.

The three jobs compared

JobFitsWhy
Your personal loginsKeePass-style vault on your phone (the Saku direction)You unlock it, entries and autofill matter, you approve each save. OpenBao is a server for apps and machines, not phone autofill.
Secrets for apps and bots run for youOpenBao, if you ever run a server for itPer-app identity, path-based access policy, audit log, versioned values, rotation for some backends.
Config secrets in a git repoSOPS with ageEncrypts the values inside env/YAML/JSON/INI/binary files. Not a vault, and it needs its own key kept somewhere safe.

What OpenBao gives (from its own docs)

  • Clients (users, machines, apps) authenticate, then get a token tied to a path-based policy. what-is-openbao
  • AppRole is meant for machines and apps, and is less useful for human operators. approle
  • KV v2 keeps versions (default 10); soft delete, undelete and destroy can each be restricted. kv
  • Audit devices log requests and responses, apart from a few system paths. audit
  • Database engine can issue per-service credentials and rotate static-role passwords for backends that support it. databases
  • Starts sealed. The default Shamir seal needs a threshold of key shares to unseal; other seal methods exist, so whether a restart needs a human depends on the setup chosen. seal
  • Storage is untrusted and holds only encrypted data; backups need a plan for storage and unseal material. storage
Caveats, stated plainly.
  • Versioning is history, not rotation. A leaked token stays valid until it is changed at the service that issued it.
  • Encrypted files in git are not automatically safer than a CI secret store. It depends on where the decryption key lives and who can reach it. (SOPS: github.com/getsops/sops; it supports age and PGP as well as cloud KMS.)
  • Self-hosting does not have to mean new spend, but I have not checked where it would run, so cost is unverified.
  • I have not checked releases, hosting options or prices. No account, signup or server was created.

Rules I would keep either way

  • My app and bot secrets stay separate from your personal vault: separate access, rotation and recovery.
  • I never hold your personal vault key. Each save goes through your unlock and approval.
  • No home-made cryptography; established open-source tools only.
