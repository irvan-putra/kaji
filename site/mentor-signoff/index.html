Mentor sign-off without accounts: what we learned building it

Build note, 22 Nov 2026. sanggup needed a way for a learner to get a mentor's sign-off across two devices while keeping its promise: no accounts, no server, nothing stored off the devices. These are the design decisions that worked, written up so other small tools can reuse them. The implementation is public: github.com/irvan-putra/sanggup (sign-off flow and the reviewer page).

The request travels inside the link

Instead of a database row, the sign-off request (which milestone, what task, when it was asked) is encoded as readable text in the share link itself, and the mentor's browser decodes it. No backend, no sync, nothing to leak from a server. The cost: anyone holding the link can read what it carries. We say exactly that next to the share button, so the learner sends it only to their reviewer. Link-carried data is convenience, not confidentiality, and the UI should never imply otherwise.

QR for the in-person case

When learner and mentor are in the same room, typing a link is silly, so the share view renders a QR of the same link. We vendored the MIT-licensed qrcode.js instead of pulling from a CDN: the app keeps working offline and no third party sees the links. If the QR library fails, the plain link field still works; the QR is a convenience, never the only path.

A short code closes the loop, and it is not identity

The mentor's decision comes back as a six-character code the learner types in. The code is derived from a hash of the request code plus the verdict, so it records that a conversation happened, nothing more. Anyone can recompute it, so it is not proof of who reviewed, and both the learner's and the reviewer's screens say so, next to the existing honesty note that a milestone records a mentor review, not a certificate or a qualification. The pattern generalizes: when a prototype cannot verify identity, put the limitation in the interface, not in a footnote.

State stays on each device, and the cost is stated

Each side keeps its own localStorage. That is what makes the no-accounts promise cheap to keep, and the real cost is no sync: requests made on one device are invisible on another until the link crosses over. We kept the old same-device demo notes and added the new limits rather than quietly dropping them.

Operational lesson: a green deploy is not a live page

The site deploys through a workflow that copies an explicit allowlist of files into the published directory. The new reviewer page and vendor library passed the whole test suite and deployed green, then 404'd, because nobody had added the new directories to the copy list. The fix was one line, but the real lesson is the check that caught it: open the actual URL after every deploy. A passing pipeline only proves the pipeline ran.

What we deliberately did not build

No mentor directory or matching, no chat, no accounts, no server sync. A directory means real people's data, moderation and safety obligations; chat duplicates the chats people already have; sync means infrastructure and spend. Each is a separate decision with its own review, not something to fold into a small feature.
