PI-Desktop: a desktop workspace for coding agents, and what to try with it

An Electron and Rust desktop app for macOS, Windows and Linux that keeps projects, sessions, agents and plugins in one place. Irvan shared it as a non-official GUI with a good look.

Status: read from the public repository and GitHub's API on 25 Nov 2026. Not downloaded or run. I could not confirm from the pages I read which official project the "pi" harness belongs to, so I make no claim about it.

What the repository says

  • Source: https://github.com/vastsa/pi-desktop, GNU LGPL v3, about 8,100 stars and 270 open issues at the time of reading. Most of the 5,000+ contributions come from one author.
  • Local-first and model-agnostic: OpenAI, Anthropic, OpenAI-compatible APIs, custom gateways, Ollama and LM Studio. Provider, model ID, context window and endpoint are set per model, and each session can use a different one.
  • Three working modes: Agent (do the task), Plan (write the approach first), Goal (fix the outcome and acceptance criteria, let the agent choose the path).
  • Subagents for background tasks, and Worker Sessions for longer parallel work, each one a full inspectable session.
  • Project, session, agent, work structure: sessions can be pinned, archived, branched and searched, and survive restarts.
  • Plugins (.piplug packages or a marketplace) can add commands, panels, floating widgets, agent tools, skills, themes, MCP servers and background services.

Things to check before relying on it

  • Version mismatch: the README says the current line is 0.24.x, but the latest published release in the API was v0.23.0 (19 Nov 2026), with DMG, AppImage and RPM files.
  • Not tried: no install, no run, no look at the permission layer beyond the README's statement that privileged operations pass through it.
  • A single main author and many open issues: fine for a trial, worth watching before depending on it.
  • It is a desktop app, so it needs a computer. Our work so far is Android and web.

What we could do with it

1. Look at the interface

The screenshots page in the repo shows the layout. Worth comparing with our own review-page and dashboard designs, since the sessions and Work Panel idea overlaps with how we review repos.

2. Point it at a gateway we use

It takes any OpenAI-compatible endpoint. Whether Fenrir's models work through it is untested, but it would be a cheap first experiment with the credit we have.

3. Write a small plugin

A plugin can add a panel and agent tools. Candidates: a Patuh-style repo consistency panel, or a Kaji notes search view. Plugin docs are at docs/plugin-development.md in the repo.

4. Use the Plan mode idea

Plan-then-execute and Goal with acceptance criteria match our habit of review pages before changes. We can copy the idea without installing anything.
